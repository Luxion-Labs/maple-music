# Maple — Local Android Development on Ubuntu

Everything you need to build, sign, and install the **Maple Android app** from a
dual-booted Ubuntu machine, without relying on CI.

The Android build is fundamentally different from the desktop builds:

- The **frontend** is a normal web app (`frontend/`, React 19 + Tailwind v4 + Vite 8,
  package manager is **bun**, NOT pnpm/npm).
- The **Rust core** is cross-compiled to `aarch64-linux-android`.
- The app is a Tauri 2 Android project rooted at `src-tauri/gen/android/` — which is now
  **committed** to git because we make an important native customization there (see
  "The native shell" below).
- It dynamically links **libmpv** (and ffmpeg), which Android has no system copy of — you
  must extract it from the official mpv-android release APK every build.

- **Maple version in this repo:** `0.4.13` (`src-tauri/tauri.conf.json`).
- **Bundle / package manager:** `bun` for `frontend/`.
- **Remote:** currently `git@github.com:akshad-exe/maple-music.git` (GitHub redirects to
  `Luxion-Labs/maple-music`). You may want to update it:
  ```bash
  git remote set-url origin git@github.com:Luxion-Labs/maple-music.git
  ```

## 1. One-time prerequisites (Ubuntu)

These are the same pieces the CI job (`.github/workflows/android-apk.yml`) assembles.
Install them once.

### Rust + the Android target

```bash
# rustup (if you don't have it), then add the aarch64 Android target
rustup default stable
rustup target add aarch64-linux-android
```

### The Tauri CLI (cargo subcommand)

Use the **prebuilt binary**, not a global npm install. The generated gradle project's
`rustBuild` tasks resolve the `cargo tauri` subcommand themselves; a globally
`npm`-installed CLI breaks there with "Cannot find module …/src-tauri/tauri".

```bash
cargo install tauri-cli --version "^2"        # or use taiki-e install-action's cargo-tauri
cargo tauri --version                          # confirm
```

### JDK, Android SDK + NDK

Tauri's `android init` needs an SDK; the gradle build needs **JDK 17+** (the CI uses 21)
and an **NDK** whose `libclang` is used by bindgen.

```bash
sudo apt install openjdk-21-jdk                # 17+ is fine

# Android command-line tools → ANDROID_HOME (pick your own path, e.g. ~/Android/Sdk)
mkdir -p "$HOME/Android/Sdk/cmdline-tools"
curl -LO "https://dl.google.com/android/repository/commandlinetools-linux-*_latest.zip"
# unzip into cmdline-tools/, the folder must be named "latest":
#   $HOME/Android/Sdk/cmdline-tools/latest/bin
"$HOME/Android/Sdk/cmdline-tools/latest/bin/sdkmanager" --install \
  "platform-tools" "platforms;android-36" "build-tools;36.0.0" "ndk;27.0.*"
```

Then export (add to your `~/.bashrc`):

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
export ANDROID_NDK_HOME=$(ls -d "$ANDROID_HOME/ndk/"* | sort -V | tail -1)
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin"
```

> `platform-tools` gives you **adb** (used to install/run on the phone), and
> `build-tools` gives you **zipalign** and **apksigner** for signing.

### Build deps (bindgen / clang)

`rquickjs-sys` runs **bindgen**, which parses C headers with libclang. On Ubuntu the NDK's
own `libclang.so` works, so point `LIBCLANG_PATH` at it (this is the big advantage of
building on Ubuntu vs Windows):

```bash
# after the NDK is installed:
export LIBCLANG_PATH="$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/linux-x86_64/lib"
```

### bun (frontend) + node (tooling)

```bash
curl -fsSL https://bun.sh/install | bash    # adds ~/.bun/bin
sudo apt install nodejs npm                 # or install node 24 via nvm
```

## 3. The three native pieces (the parts CI does for you)

A desktop build gets libmpv + media libs for free; Android does not. Three things must
happen before `cargo tauri android build` will succeed.

### A. Generate the Android project

`src-tauri/gen/android/` is generated by Tauri. It's committed so our native
customization (MainActivity) persists, but you may need to regenerate after a Tauri
upgrade — `cargo tauri android init` re-creates it:

```bash
cargo tauri android init
```

**This is fine because `MainActivity.kt` is preserved / re-created; if it regenerates the
file, re-apply the edge-to-edge change in section 6.**

### B. Extract libmpv + ffmpeg + cacert.pem from mpv-android

The app links `libmpv` at build time and needs it (plus everything ffmpeg links
dynamically) at runtime. Both come from the official mpv-android release APK. The version
is pinned in CI — match it:

```bash
export MPV_ANDROID_APK_URL="https://github.com/mpv-android/mpv-android/releases/download/2026-08-11/app-default-arm64-v8a-release.apk"
export JNI_DIR="src-tauri/gen/android/app/src/main/jniLibs/arm64-v8a"

curl -fsSL -o /tmp/mpv-android.apk "$MPV_ANDROID_APK_URL"
mkdir -p "$JNI_DIR"

# EVERYTHING under lib/arm64-v8a, not just libmpv.so — mpv links ffmpeg (libav*) and
# libc++_shared dynamically. Shipping only libmpv.so makes the app close instantly on open.
unzip -j -o /tmp/mpv-android.apk "lib/arm64-v8a/*.so" -d "$JNI_DIR"

# cacert.pem rides along: ffmpeg's TLS layer on Android has no system cert store, so https
# streams fail unless tls-ca-file points at this bundle (include_bytes!-d by the player crate).
unzip -j -o /tmp/mpv-android.apk "assets/cacert.pem" -d crates/player/

# Second copy into the NDK sysroot's triple-lib dir: the linker searches there for -lmpv,
# and this survives the Tauri CLI's target-scoped RUSTFLAGS injection (which overrides
# any -L you export).
SYSROOT_LIB="$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/linux-x86_64/sysroot/usr/lib/aarch64-linux-android/24"
cp "$JNI_DIR"/lib*.so "$SYSROOT_LIB/"
```

Sanity checks:

```bash
test -f "$JNI_DIR/libmpv.so"   && echo "libmpv ok"
test -f "$JNI_DIR/libavcodec.so" || echo "MISSING ffmpeg libs — libmpv.so will not load"
test -f crates/player/cacert.pem && echo "cacert ok"
```

> The `.so` files and `cacert.pem` are **gitignored** (see `src-tauri/gen/android/.gitignore`
> and the repo `.gitignore`). Don't commit them.

### C. Toolchain env for bindgen

bindgen needs to parse the Android sysroot headers, not the host's, else it produces
wrong-size bindings. Add to your `~/.bashrc` (or export before building):

```bash
export BINDGEN_EXTRA_CLANG_ARGS="--sysroot=$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/linux-x86_64/sysroot --target=aarch64-linux-android24"
```

## 4. Build

### a. Frontend bundle first

```bash
cd frontend && bun run build && cd ..
```

### b. Build the unsigned ARM64 release APK

```bash
# --config overrides beforeBuildCommand so tauri doesn't run `bun run build` from the
# repo root (which has no frontend/package.json at the root).
cargo tauri android build --apk --target aarch64 \
  --config '{"build":{"beforeBuildCommand":""}}'
```

Output lands at:
`src-tauri/gen/android/app/build/outputs/apk/*-unsigned.apk`

### c. (Debug) println/loggrade

For faster iteration during development you can also do a debug build, which is debuggable
and ships debug symbols:

```bash
cargo tauri android build --apk --target aarch64 --debug \
  --config '{"build":{"beforeBuildCommand":""}}'
```

## 5. Sign + install on the phone

Release APKs must be signed to install. There's already a committed `maple-release.jks`
at the repo root; its password is deliberately public (`maple123`) — this is a free client
anyone builds from source. Use it so new builds install over old ones:

```bash
BT="$ANDROID_HOME/build-tools/36.0.0"          # or: ls "$ANDROID_HOME"/build-tools/* | sort -V | tail -1
UNSIGNED="$(find src-tauri/gen/android/app/build/outputs/apk -name '*-unsigned.apk' | head -1)"

zipalign -f 4 "$UNSIGNED" maple-arm64-aligned.apk
apksigner sign --ks maple-release.jks --ks-key-alias maple \
  --ks-pass pass:maple123 --key-pass pass:maple123 --out maple-mobile.apk maple-arm64-aligned.apk
apksigner verify maple-mobile.apk
ls -la maple-mobile.apk
```

If `maple-release.jks` were ever missing, mint a new one (and commit it so everyone shares
the signature):

```bash
keytool -genkeypair -keystore maple-release.jks -alias maple \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass maple123 -keypass maple123 -dname "CN=Maple"
```

**Install on the phone** (enable Developer options → USB debugging on the vivo V23, plug
in over USB):

```bash
adb devices                    # confirm the phone shows as authorized
adb install -r maple-mobile.apk
```

If adb doesn't see the device, try `adb kill-server && adb start-server`, and on the phone
set USB mode to **File transfer / MTP** (not "Charge only").

> Because the signed artifacts (`maple-mobile.apk`, `maple-arm64-aligned.apk`) are build
> outputs not source, they're in the repo `.gitignore`. Copying one to the repo root for
> transfer to the phone is fine — just don't commit it.

## 6. The native shell (important — safe-area / status-bar handling)

`src-tauri/gen/android/` is **committed** because the generated `MainActivity` needed a
hand-edited fix: the React app must not draw under the Android status bar / gesture bar.

**What was wrong:** Tauri enables edge-to-edge by default, so the WebView spans the whole
screen including under the status bar and nav bar. On the vivo V23 (Android 12, API 32)
edge-to-edge is **not** OS-enforced, and this made the top bar hide under the status bar,
the bottom nav slide under the phone's home/back buttons, and `100dvh` layouts overflow
the visible screen.

**The fix** keeps the window in the default `decorFitsSystemWindows` mode on API < 35:

```kotlin
// src-tauri/gen/android/app/src/main/java/com/maple/music/MainActivity.kt
package com.maple.music

import android.os.Bundle
import androidx.core.view.WindowCompat

class MainActivity : TauriActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        WindowCompat.setDecorFitsSystemWindows(window, true)
    }
}
```

`androidx.core.view.WindowCompat` ships with `androidx.core`, which is pulled in by
`androidx.appcompat` / `androidx.activity-ktx` (see `app/build.gradle.kts`), so it compiles
without extra deps.

**On Android 15+ (API 35+), edge-to-edge is enforced by the OS** and
`setDecorFitsSystemWindows(true)` is a no-op. If you later run on Android 15+, content will
draw under the bars again and the correct fix is the CSS-var approach that requires an
`onWebViewCreate` override in `MainActivity` (injecting real insets into
`--safe-area-inset-top/bottom`, which the frontend's `.pt-safe`/`.pb-safe` utilities read,
falling back to `env()`). Don't do both at once — they double the padding.

## 7. Pitfalls & gotchas

- **bindgen / rquickjs-sys:** the Rust crate `rquickjs-sys` pins `bindgen 0.69.5`. On
  **Windows** the MSVC toolchain + missing `libclang.dll` breaks it (and Rust 1.95 changed
  2024-edition patterns that old bindgen can't parse). On Ubuntu with
  `LIBCLANG_PATH` + `BINDGEN_EXTRA_CLANG_ARGS` from §1/§3 it works. If rustup's current
  toolchain still fails, install an older one:
  ```bash
  rustup toolchain install 1.80.0 --profile minimal --target aarch64-linux-android
  cargo +1.80.0 tauri android build --apk --target aarch64
  ```
- **Don't use `git add -A` blindly:** it picks up `crates/player/cacert.pem` (gitignored,
  so actually safe), `.hermes/`, and the downloaded APK. Stage the files you intend.
- **jniLibs is ~38 MB and CI-fetched** — it's ignored via `src-tauri/gen/android/.gitignore`
  (`app/src/main/jniLibs`). Keep it that way.
- **Concurrency on CI:** the workflow's `concurrency` group cancels an in-progress APK build
  when a new main push lands. If you're waiting on an APK from CI and then push again, the
  earlier run is cancelled — watch the **latest** run.
- **Frontend is `frontend/` (React + bun), not `ui/`** (dead SvelteKit). Don't run pnpm
  builds; use `cd frontend && bun install && bun run build`.
- **NDK version:** pin the same NDK major that CI/Gradle expects. If the AGP version in
  `src-tauri/gen/android/gradle.properties` wants a specific NDK, `sdkmanager` will tell you.

## 8. Quick reference (copy-paste one-shot)

Assumes the exports from §1/§3 are in your shell.

```bash
# fresh clone → build → signed APK, in one block
cd frontend && bun install && bun run build && cd ..

export MPA="https://github.com/mpv-android/mpv-android/releases/download/2026-08-11/app-default-arm64-v8a-release.apk"
curl -fsSL -o /tmp/mpv.apk "$MPA"
unzip -j -o /tmp/mpv.apk "lib/arm64-v8a/*.so" -d src-tauri/gen/android/app/src/main/jniLibs/arm64-v8a
unzip -j -o /tmp/mpv.apk "assets/cacert.pem" -d crates/player/
cp src-tauri/gen/android/app/src/main/jniLibs/arm64-v8a/*.so \
  "$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/linux-x86_64/sysroot/usr/lib/aarch64-linux-android/24/"

cargo tauri android build --apk --target aarch64 --config '{"build":{"beforeBuildCommand":""}}'

UNSIGNED="$(find src-tauri/gen/android/app/build/outputs/apk -name '*-unsigned.apk' | head -1)"
BT="$ANDROID_HOME/build-tools/36.0.0"
"$BT/zipalign" -f 4 "$UNSIGNED" maple-arm64-aligned.apk
"$BT/apksigner" sign --ks maple-release.jks --ks-key-alias maple \
  --ks-pass pass:maple123 --key-pass pass:maple123 --out maple-mobile.apk maple-arm64-aligned.apk
"$BT/apksigner" verify maple-mobile.apk

adb install -r maple-mobile.apk
```
